# Store ERP — Flutter Desktop (Windows)

واجهة عربية باتجاه RTL لإدارة متجر محلي دون الحاجة إلى اتصال إنترنت أثناء التشغيل، باستخدام Flutter + Material 3 + Provider + SQLite (`sqflite_common_ffi`). يحتوي المشروع على شاشة تسجيل الدخول، لوحة التحكم، و21 وحدة عمل وإدارة (23 شاشة مع شاشة الدخول ولوحة التحكم).

## المتطلبات
- Flutter SDK حديث (Dart 3.3 أو أحدث)
- Windows مع Visual Studio وDesktop development with C++ لتجميع تطبيقات Windows

## التشغيل
من داخل مجلد المشروع:

```powershell
flutter config --enable-windows-desktop
flutter create --platforms=windows .
flutter pub get
flutter run -d windows
```

## إنشاء EXE
```powershell
flutter build windows --release
```
الملفات التنفيذية تكون عادةً في `build\windows\x64\runner\Release\`؛ وزّع المجلد كاملًا بما فيه ملفات DLL وdata، وليس ملف EXE وحده.

## دخول أول مرة
- اسم المستخدم: `admin`
- كلمة المرور: `admin`

**غيّر كلمة المرور قبل إدخال بيانات حقيقية.** بيانات الدخول الافتراضية للتجربة فقط. لا يعتبر هذا الإصدار نظامًا محاسبيًا معتمدًا أو جاهزًا للإنتاج قبل مراجعة الصلاحيات، تشفير كلمات المرور، واختبار إجراءات الترحيل والتسويات.

## ما هو موجود
- 23 شاشة بين الدخول ولوحة التحكم ووحدات الأصناف والعملاء والموردين والمستخدمين والمبيعات والمشتريات والمرتجعات والمخزون والتحويلات والتالف والصناديق والجرد والتقارير والنسخ الاحتياطي والإقفال.
- قاعدة SQLite محلية تنشأ عند أول تشغيل، مع جداول للبيانات الرئيسية، رؤوس الفواتير وبنودها، أرصدة المخزون، الصناديق، الجرد، وسجل النسخ الاحتياطية.
- عمليات CRUD العامة (إضافة/عرض/بحث/تعديل/حذف) للوحدات التي تسمح بها قيود قاعدة البيانات.
- تصدير السجلات المعروضة إلى CSV، ونسخ قاعدة البيانات إلى مجلد Documents\StoreERP\backups.
- واجهة RTL قابلة للتغيير بين قائمة جانبية كاملة ومختصرة.

## حدود مهمة
هذا مشروع تطبيق أولي قابل للتوسعة، وليس نظام ERP مكتملًا للاستخدام التجاري بعد. شاشات المبيعات والمشتريات الحالية تدير رأس الفاتورة عبر CRUD عام ولا توفر بعد واجهة متكاملة لإضافة البنود واعتماد/عكس كل القيود المحاسبية. شاشة الاسترجاع من نسخة احتياطية، التقارير المالية التفصيلية، ترحيل المشتريات والتحويلات والجرد، صلاحيات دقيقة لكل مستخدم، والتدقيق الأمني تحتاج تنفيذًا واختبارًا إضافيين. لم يتم بناء EXE في بيئة إنشاء هذا الأرشيف لعدم توفر Flutter SDK هنا؛ يجب تنفيذ أوامر البناء أعلاه على جهاز Windows مثبت عليه Flutter.

## مكان قاعدة البيانات
تُحفظ قاعدة البيانات `local_store.db` داخل مجلد Application Support الخاص بالتطبيق. النسخ الاحتياطية تصدر إلى مجلد Documents الخاص بالمستخدم تحت `StoreERP/backups`.


## مراجعة الواجهات العشر الأولى
تمت مراجعة وحدات الأصناف والعملاء والموردين والمستخدمين والمبيعات ومرتجع البيع والمشتريات وأرصدة المخزون وتحويل المخازن وسند التالف. تشمل التحسينات التحقق من الحقول المطلوبة والتواريخ، توليد أرقام أولية للمستندات، تجزئة كلمات المرور الجديدة، حماية الأرصدة من التعديل المباشر، ومنع تحرير حالة الترحيل يدويًا في التحويلات، وإعادة حساب إجماليات الفواتير عند حفظ الرأس.

لتكرار الفحص البنيوي على Python 3: `python tooling/audit_first_10.py`. هذا الفحص لا يغني عن `flutter analyze`, `flutter test`, أو اختبار التشغيل على Windows.
